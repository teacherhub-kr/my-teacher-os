# 음악 교과세특 작성실 — 영구 저장 설계안 (미구현 · 학교 승인 대기)

상태: **설계만 완료.** 실제 저장소·버튼은 없습니다. 현재 작성실(v67.2)은 브라우저 창 메모리에만 두며, 새로고침하면 사라집니다.

## 1. 왜 지금 저장하지 않는가

- 세특 근거(관찰 기록·초안)는 학생 개인정보입니다. 새 저장 장소를 만들려면 학교의 개인정보 처리 기준, 접근권한, 보유기간 확인이 먼저 필요합니다.
- 브라우저 저장소(공개·비공개 모두)는 공용 PC·다중 계정에서 유출·혼입 위험이 있어 사용하지 않습니다.

## 2. 승인 시 권장 구조

| 항목 | 설계 |
|---|---|
| 위치 | 교사 본인(또는 학교) Google 계정의 **별도 비공개 스프레드시트** `세특작성_2026_2학기`. 수행평가 원본·채점원본·`평가통합현황`과 **다른 파일** |
| 연결 | 기존 Script Properties에 별도 키 `SETEUK_STORE_ID` 추가. 원본 시트 ID와 분리 |
| 쓰기 범위 | 이 저장 파일에만 쓰기. 원본 성적 파일에 쓰는 코드는 없으며 CI 테스트로 계속 금지 |
| 저장 단위 | 학급별 1행/학생. 열: 학급, 번호, 이름(원본 대조용), 입력 대상(확인 필요/대상/제외), 활동명, 관찰, 산출물 확인, 변화, 초안, 근거 지문(필드별), 상태, 수정 시각 |
| 저장하지 않는 것 | **논술 원문**(데이터 최소화), 점수(원본에서 매번 조회), 교사 확정 표시와 문장별 사실 확인(복원 후 교사가 다시 확인) |
| 복원 규칙 | 학급 일치 + 번호 + 이름이 현재 Google 원본 명렬과 **정확히 일치**할 때만 복원. 불일치는 표시하지 않고 목록으로 경고 |
| 동시 편집 | 행 단위 수정 시각 비교, 충돌 시 덮어쓰지 않고 중단 |
| 보유·파기 | 학년도 종료 + 학교 기준 기간 후 파일 단위 삭제(교사 수행) |
| 권한 | 웹앱 `나로 실행 / 나만 접근` 유지. 저장 파일 공유 금지 |

## 3. 이미 검증한 부분 (가상 데이터)

`Index.html`의 `exportRecordWork_` / `restoreRecordWork_`(UI 미연결)와 `tests/seteuk-room-v67.test.js`:

- 논술 원문이 저장 데이터에 포함되지 않음
- 이름 불일치·학급 불일치·형식 오류는 복원 거부
- 복원 후 교사 확정·사실 확인은 초기화
- 저장 당시 근거 지문과 다르면 `근거 변경`으로 표시

## 4. 결정이 필요한 사항 (학교·교사)

1. 저장 위치(개인 계정 vs 학교 계정) 승인
2. 보유기간
3. 세특 입력 대상 범위(학업성적관리위원회 심의 결과)
