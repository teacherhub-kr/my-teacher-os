# MY MUSIC CLASS — Google Apps Script 교사 전용 대시보드

기존 MY TEACHER OS와 원본 Google Sheets를 **개별 성적의 공개 노출 없이** 연결하는 방식입니다.

- **원본:** 이미 소유한 \`2026_2학기_음악_가변형_수업_수행평가_스케줄\` Google Sheets
- **비공개 조회:** 이 시트에 연결된 Google Apps Script 웹앱
- **사용 화면:** Teacher OS의 [교사 전용 화면 열기] 버튼
- **보안:** 웹앱 배포를 반드시 **나로 실행 / 나만 접근**으로 제한
- **Google Cloud:** 별도의 OAuth 클라이언트 ID나 직접 만든 OAuth 동의 화면은 불필요. 첫 실행 때 Google Apps Script의 기본 권한 승인만 필요
- **입력·저장:** 원본 시트의 셀·명렬표·수식·점수는 수정하지 않습니다. 집계는 `평가통합현황!A3:K18`에서 읽고, 학생별 조회 요청이 들어올 때만 개별 채점원본의 번호·이름·점수·평가상태를 읽습니다.

## 학생별 성적 조회 (v57)

교사 본인이 조회할 때만 **반 선택 → 해당 반 학생 조회**에서 학생 번호, 이름, 수행평가 1~4차 점수와 평가상태를 볼 수 있습니다. 보호된 Google Apps Script 웹앱 안에서만 처리하며, 공개 GitHub Pages Teacher OS에는 학생정보를 보내지 않습니다.

- 2학년: 기존 1~4차 채점원본 4개를 읽습니다.
- 3학년: 1·2차는 통합 시트의 성적근거표(1학기 자료), 3·4차는 채점원본 2개를 읽습니다.
- 학생 이름·번호가 서로 다른 원본은 잘못 합치지 않도록 **전체 해당 반 조회를 중단**합니다. 공란은 0점으로 환산하지 않습니다.
- 결시 사유·관찰 메모 같은 자유기술 데이터는 반환하지 않습니다.
- 학생정보는 앱 실행 메모리의 화면에만 표시하며 로컬 저장소, URL, GitHub 파일에는 기록하지 않습니다.
- 웹앱은 반드시 **나로 실행 / 나만 접근**으로 배포해야 합니다. 단지 내가 만든 사이트라는 사실만으로 외부 접근이 차단되는 것은 아닙니다.

## 음악 교과세특 작성실 (v67)

교사 전용 화면 상단의 **✎ 음악 교과세특 작성실** 버튼, 또는 MY TEACHER OS의 **학생·생활기록부 → 음악 교과세특 작성 ↗** 탭으로 바로 이동합니다(`?view=seteuk`).

- 학급을 고르고 **이 반 학생 불러오기** → 기존 수행평가 원본 명렬을 그대로 사용합니다. 명단을 다시 입력하지 않습니다.
- 학생별로 활동명, 직접 관찰한 사실(필수), 논술·과제에서 교사가 확인한 내용, 변화·결과를 입력하고 **근거로 초안 작성**을 누릅니다. 입력한 근거만 이어 붙이며 점수·태도·역량을 추정해 넣지 않습니다.
- 논술 원문은 접이식 칸에 붙여넣어 읽기용으로만 씁니다. 초안에 자동 포함하지 않고 서버로 보내지 않습니다. 파일(PDF·HWP·DOCX·이미지) 자동 추출은 **지원하지 않습니다**.
- 길이: 2026 중학교 기재요령 p.162 기준 과목별 세특 500자(한글 3Byte, 영문·숫자 1Byte, 엔터 1Byte). 1500Byte보다 높게 설정할 수 없습니다.
- 기재 점검: ‘기재 불가’(p.18~19, p.104 — 교내·외 대회 참여·실적, 방과후학교, K-MOOC·MOOC·KOCW, 연구보고서(소논문) 등)는 확정을 막고, ‘확인 필요’는 경고만 합니다. **탐지되지 않았다고 기재 가능한 것은 아닙니다.**
- 문장별 근거 대조: 각 문장에 연결된 교사 근거를 보여 주지만 이는 **어휘 연결일 뿐 사실 검증이 아닙니다**. 교사가 문장마다 ‘사실 확인’을 체크해야 확정할 수 있습니다.
- 근거(관찰·산출물 확인·변화·활동명, 산출물 근거 사용 시 논술 원문)가 바뀌면 바뀐 항목을 표시하고 확정을 해제합니다.
- 세특 입력 대상 범위는 학업성적관리위원회 심의 사항이므로 학생마다 ‘확인 필요/대상/제외’를 표시합니다.
- 작성 상태: 근거 미등록 → 근거 등록 → 초안 → 검토 중 → 교사 확정(임시). 진행 현황은 이 창의 임시 현황이며 누적 기록이 아닙니다.
- **저장하지 않습니다.** 입력·초안·상태는 창을 닫거나 새로고침하면 사라지며, 닫기 전에 경고합니다. 승인 후 적용할 저장 설계는 [SETEUK_STORAGE_DESIGN.md](./SETEUK_STORAGE_DESIGN.md)에 있습니다.

### 이미 배포한 웹앱에 v67 반영하기 (교사 직접 수행)

1. 원본 스프레드시트 → **확장 프로그램 → Apps Script**에서 `Index` 파일 내용을 이 저장소의 [Index.html](./Index.html)로 교체하고 저장합니다. `Code.gs`·`StudentDetails.gs`·`appsscript.json`은 바꾸지 않습니다.
2. **배포 → 배포 관리 → (기존 웹앱) 편집(연필) → 버전: 새 버전 → 배포**. 새 배포를 만들면 주소가 바뀌므로 기존 배포를 편집합니다.
3. 접근 권한이 여전히 **나로 실행 / 나만 접근**인지 확인합니다.
4. 교사 화면 맨 아래에 **화면 버전 v67.3-seteuk**이 보이면 반영된 것입니다. 보이지 않으면 아직 이전 버전이 배포된 상태입니다.

## Google 승인 범위와 실제 데이터 안전성

**중요:** 이 코드에서 사용하는 `SpreadsheetApp.openById()`는 Google 공식 명세상 **`spreadsheets` 권한**을 요구하며 `spreadsheets.readonly`만으로는 실행되지 않습니다. 그래서 Apps Script 최초 승인 시 Google 스프레드시트 관리/편집 범위가 표시될 수 있습니다. **권한이 넓은 것과 코드가 실제로 데이터를 수정하는 것은 별개**입니다. 현재 코드는 원본의 시트·성적을 `getDisplayValues()`로 읽기만 하며, 원본에 쓰는 코드는 없습니다. 예외적으로 최초 설정 시 비공개 **Script Properties**에 원본 문서의 식별자만 저장합니다.

기존 프로젝트의 `appsscript.json`을 바꿀 필요는 없지만, **제공된 매니페스트를 직접 적용할 때는** `https://www.googleapis.com/auth/spreadsheets`와 `https://www.googleapis.com/auth/script.storage`를 사용합니다. `spreadsheets.readonly`로 바꾸면 실행 권한이 부족할 수 있습니다. Apps Script는 기본적으로 코드에서 필요한 권한을 자동 감지합니다.

**실데이터 대조 결과:** 3학년 4~9반에서는 1·2차 성적근거에 존재하고 3·4차 채점원본에는 존재하지 않는 학생번호가 반마다 1~2개 있습니다. 학생번호·이름이 겹치는 학생은 원본 간 일치하지만, 누락된 3·4차는 **0점이 아니라 ‘원본 없음’**으로 보여 줍니다. 전출·결시 등 사유는 교사가 원본에서 직접 확인해야 하며 추정하지 않습니다. 학급별 동일 번호가 두 번 등장하면 조회를 중단합니다.

## 한 번만 하는 실제 연결

**시트 소유자 Google 계정으로 진행하십시오.** 개인 계정 소유 자료라면 개인 계정으로 크롬에 로그인합니다. 학교 계정과 섞여 있는 경우 크롬 프로필을 구분하는 것이 좋습니다.

1. 원본 스케줄표를 엽니다. 상단에서 **확장 프로그램 → Apps Script**를 선택합니다.
2. 새로 열린 **이 시트에 연결된** Apps Script 편집기의 \`Code.gs\`에 [Code.gs](./Code.gs) 전체 내용을 붙여넣습니다. 기존 스크립트가 있을 경우 **덮어쓰지 마세요**. 대신 새 \`MusicDashboard.gs\` 파일을 만들고 내용을 넣으며, 동일한 이름의 함수가 없는지 확인합니다.
3. 왼쪽 `+` → **스크립트** → 파일명 `StudentDetails`를 추가하고 [StudentDetails.gs](./StudentDetails.gs)를 붙여넣습니다. 이어서 **HTML** → 파일명 `Index`를 추가하고 [Index.html](./Index.html)을 붙여넣습니다. 기존 스크립트 파일을 덮어쓰지 않습니다.
4. **기존 스크립트 프로젝트의 `appsscript.json`은 수정하지 않는 것을 기본값으로 합니다.** Apps Script가 필요한 기본 권한을 자동 감지할 수 있습니다. 새 독립 프로젝트에서 최소 권한을 명시하고 싶은 경우에만 [appsscript.json](./appsscript.json)을 참고하십시오. 기존 매니페스트를 통째로 덮어쓰면 다른 업무 자동화가 중단될 수 있습니다.
5. **저장**하고, 함수 선택에서 \`initializeDashboard\`를 실행합니다. Google의 Apps Script 권한 승인 창이 뜨면 **본인 계정**인지 확인하고 권한을 승인합니다. 출력에 \`classes: 15\`가 나오는지 확인합니다. 이 작업은 **Script Properties에 원본 시트 ID를 저장할 뿐**, 원본 시트의 셀을 수정하지 않습니다.
6. **배포 → 새 배포 → 유형: 웹 앱**을 선택합니다. 아래 조건을 엄수합니다.
   - **다음 사용자 인증 정보로 실행:** 나(Me)
   - **액세스 권한이 있는 사용자:** 나만(Only myself)
   - \`모든 사용자/Anyone\`나 \`링크가 있는 모든 사람\`으로 절대 배포하지 마세요.
7. 배포가 끝나면 나온 \`https://script.google.com/macros/s/.../exec\` 주소를 복사합니다.
8. [MY TEACHER OS](https://teacherhub-kr.github.io/my-teacher-os/)에서 **음악 수행평가 · 교사 전용 대시보드 → 웹앱 주소 연결**을 열고 \`/exec\` 링크를 입력한 뒤 **주소 저장**을 누릅니다.
9. **교사 전용 화면 열기**를 클릭하여 15개 반 집계가 보이는지 확인한 후, 학급을 선택해 **해당 반 학생 조회**를 누릅니다. 이름과 점수를 기존 원본 채점표와 표본 대조합니다.

## 중요한 차이

- Google OAuth 웹 클라이언트를 새로 만들 필요는 없지만, **Apps Script가 시트를 읽도록 최초 권한을 승인하는 과정은 있습니다.**
- Teacher OS는 \`/exec\` URL만 **이 브라우저 localStorage**에 저장합니다. 웹앱 접속 시 Google 계정 인증은 Google이 처리합니다.
- \`/exec\` 주소를 알고 있다고 아무나 조회할 수 있는 구조가 아닙니다. **배포 권한이 ‘나만’인지 확인하는 것이 필수**입니다.
- 웹앱으로 읽은 학급별 집계는 **교사 전용 웹앱 안에서만** 보입니다. 공개 GitHub Pages Teacher OS로 성적·학생정보가 복사되지 않습니다.
- 원본의 \`미채점 0명\`은 수업 실시 또는 보충평가 완료 확정이 아닙니다.
- **3학년 1·2차는 1학기 참고 자료**, 3·4차가 2학기 수행평가입니다.
- 앞으로 원본의 학급 수·열·제목이 바뀌면 오류 메시지로 실패하도록 설계했습니다. 잘못된 수치를 정상처럼 표시하지 않습니다.

## 점검 및 문제 해결

- **‘접근 권한 없음’** → 배포한 Google 계정과 크롬 로그인 계정이 일치하는지 확인합니다. 개인 계정 소유면 개인 계정으로 로그인하세요.
- **‘초기 설정이 없습니다’** → 스크립트 편집기에서 \`initializeDashboard\`를 1회 실행합니다.
- **‘집계표 제목이 변경되었습니다’** → 원본의 \`평가통합현황!A3:K18\` 구조를 확인합니다. 기존 점수는 수정하지 마세요.
- **변경된 코드가 반영되지 않음** → Apps Script의 **배포 관리 → 편집 → 새 버전**으로 업데이트합니다. 코드를 저장하는 것만으로 기존 배포가 자동 업데이트되지는 않습니다.
- **교사용 화면이 열리지 않음** → 배포가 \`Only myself\`인지, 주소가 \`/exec\`인지, 팝업 차단 여부와 Google 다중 로그인 상태를 확인합니다.

## 한계: 사용자 계정 조작이 필요한 구간

연결된 Google Drive 도구는 스프레드시트를 읽을 수 있지만 **Apps Script 편집기 프로젝트 생성·권한 승인·웹앱 배포는 수행할 수 없습니다**. 따라서 이 저장소의 코드를 구현·검증하는 것과 **개인 계정의 실제 웹앱 배포 완료**는 별개입니다. 실제 배포 URL이 나오기 전에는 원본이 Teacher OS에 '자동 연결 완료'됐다고 보고하지 않습니다.
